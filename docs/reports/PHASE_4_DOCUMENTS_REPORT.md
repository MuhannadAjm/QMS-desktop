## 5. Database Changed

**Yes.** Migration 003 added `original_file_name TEXT` to `documents` and `document_revisions`.

The column is needed to store the user-visible filename (e.g. `Quality_Policy_v1.pdf`) separately from the on-disk stored filename (e.g. `42_1718345678901234.pdf`). This allows renaming and collision-free storage without changing the user-facing name.

## 6. Auto-Numbering

Document numbers are generated by `generate_doc_number()` in `documents.rs`:

```rust
let prefix = get_document_prefix(conn)?;  // reads 'document_prefix' from settings table
let year: String = conn.query_row("SELECT strftime('%Y', 'now')", [], |row| row.get(0))?;
let count: i64 = conn.query_row(
    "SELECT COUNT(*) FROM documents WHERE doc_number LIKE ?1",
    params![format!("{}-{}-%" , prefix, year)],
    |row| row.get(0),
)?;
Ok(format!("{}-{}-{:04}", prefix, year, count + 1))
```

Example output: `DOC-2026-0001`, `DOC-2026-0002`. The prefix defaults to `"DOC"` if the setting is empty or missing.

## 7. File Storage Implementation

### Flow

1. JS opens file picker: `open({ multiple: false, filters: [...] })` via `@tauri-apps/plugin-dialog`
2. Returns path string: e.g. `C:\Users\alice\Desktop\Policy.pdf`
3. JS passes path to `attach_document_file` Rust command
4. Rust validates extension (whitelist: `pdf`, `doc`, `docx`, `xls`, `xlsx`, `png`, `jpg`, `jpeg`)
5. Rust generates stored filename: `{document_id}_{timestamp_micros}.{ext}`
6. Rust copies file: `std::fs::copy(source, dest)`
7. Rust updates `documents.file_path` (stored name) and `documents.original_file_name` (user name)
8. Rust inserts revision entry and activity log entry
9. Returns updated `DocumentListItem`

### File path in DB

- `file_path` = stored filename only (e.g. `42_1718345678.pdf`) — used to reconstruct full path
- `original_file_name` = user-visible name (e.g. `Quality_Policy_v1.pdf`)

Full path reconstructed: `%APPDATA%\QMSDesktop\uploads\documents\{file_path}`

### Opening files

`open_document_file` uses:
```rust
std::process::Command::new("cmd")
    .arg("/c").arg("start").arg("")  // "" = window title (required when path has spaces)
    .arg(&path_str)
    .spawn()?;
```

This opens the file using the Windows default application (Acrobat for PDF, etc.).

## 11. UI Components Implemented

### KPI Cards
4 `StatCard` components — Total Documents (navy), Controlled (green), Under Process (amber), Obsolete (gray). Clicking a count card toggles the corresponding status filter.

### Filter Bar
- Text search: matches doc_number, title, owner_name, category
- Status dropdown: All / UNDER PROCESS / CONTROLLED / OBSOLETE
- Type dropdown: All / 8 document types
- Clear button: appears when any filter is active

### Data Table
Columns: Doc Number (monospace), Title (with file indicator), Type (pill badge), Version, Status (StatusBadge), Owner, Approval Date. Click any row to open DetailsDrawer.

### DetailsDrawer (440px fixed right panel)
- Header: doc_number badge, title, StatusBadge, edit/close buttons
- **Details tab**: metadata 2-col grid (type, version, status + change link, owner, approval date, last revised, created, updated) + description + file section
- **Revisions tab**: revision cards (version badge, file name, summary, author, date)
- **Activity tab**: timeline with action badge (Created/Updated/Status Changed/File Attached), description, performer, date

### File Section (Details tab)
- Shows current attached filename with "Open" link
- "Attach File" / "Replace File" button → triggers file dialog
- After file selected: inline form shows filename + optional summary input + Save/Cancel buttons
- Progress state: "Uploading…" during attach

### DocumentModal (Create/Edit)
Fields: Title* (text), Document Type* (select), Version (text, default "1.0"), Owner (select, active users), Approval Date (date picker), Description (textarea). Error display. Loading state.

### StatusModal
Shows current → target status transition. Status dropdown excludes current status. Confirm button.
