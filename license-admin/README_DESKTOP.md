# QMS License Admin — Desktop App

Standalone Windows desktop application for managing QMS Desktop licenses.
Built with Tauri 2 (Rust + WebView2) wrapping the existing React/Vite UI.

---

## What this is

- Internal tool for license management. Not distributed to customers.
- Opens a desktop window with the License Admin portal UI.
- Connects to Supabase over the internet (no localhost required).
- Login is required. Only users in `license_admin_profiles` can access it.
- No VS Code, no `npm run dev`, no browser needed after installation.

## Environment setup (required before building)

Copy `.env.example` to `.env.local` and fill in your Supabase project values:

```
VITE_SUPABASE_URL=https://YOUR_PROJECT_ID.supabase.co
VITE_SUPABASE_ANON_KEY=your_supabase_anon_key_here
```

**NEVER commit `.env.local`.** It is in `.gitignore`.

Do NOT add service role key, private key, Resend key, or hash secret here. They are not needed.


## Install on another device

1. Copy `QMS-License-Admin-1.0.0-test.msi` (or `-setup.exe`) to target machine.
2. Run the installer. No internet required for installation.
3. Open **QMS License Admin** from Start menu.
4. Log in with your Supabase admin account.
5. Internet is required for login and all license operations.

---

## Adding admin users

Admin users must have a row in the `license_admin_profiles` Supabase table.

Steps:
1. Create a user in your Supabase project's Authentication > Users section.
2. Insert a row in `license_admin_profiles`:
   ```sql
   INSERT INTO license_admin_profiles (id, role)
   VALUES ('<user-uuid>', 'admin');
   ```
   Role can be `admin` or `viewer`.
3. The user can now log in to the desktop app.

## Architecture

```
license-admin/
  src/                    React + TypeScript UI (unchanged)
  src-tauri/
    Cargo.toml            Minimal Tauri 2 Rust crate (no custom commands)
    src/lib.rs            tauri::Builder::default().run()
    src/main.rs           Entrypoint — no console window in release
    build.rs              tauri_build::build()
    tauri.conf.json       App name, bundle ID, window config, CSP
    capabilities/         Core Tauri permissions only
    icons/                Generated by `tauri icon source-icon.png`
  .env.example            Template — copy to .env.local before building
  .env.local              NOT committed — fill in Supabase values
  package.json            Includes @tauri-apps/cli, tauri script
  vite.config.ts          Dev port 1421 (different from QMS Desktop's 1420)
```

All API calls go through the WebView JavaScript (Supabase JS client). No Rust HTTP layer.

## Security

| Item | Status |
|---|---|
| `SUPABASE_SERVICE_ROLE_KEY` in app | NOT embedded — server-side only |
| `LICENSE_PRIVATE_KEY_PEM` in app | NOT embedded |
| `RESEND_API_KEY` in app | NOT embedded |
| `LICENSE_KEY_HASH_SECRET` in app | NOT embedded |
| Admin Edge Functions protected | `requireAdmin()` checks JWT + `license_admin_profiles` |
| Anonymous access to admin functions | Blocked (401/403) |
| Frontend env vars | `VITE_SUPABASE_URL` + `VITE_SUPABASE_ANON_KEY` only |

## Known issues

- **Offline login not possible** — Supabase auth requires internet. If internet is unavailable, the login page shows a network error. This is expected.
- **Session persistence** — Supabase JS stores sessions in `localStorage` inside the WebView. Sessions persist between app restarts on the same machine.
- **Icon is minimal** — The teal "LA" icon is a placeholder. Replace `src-tauri/source-icon.png` with a proper 512x512 PNG and re-run `npx tauri icon src-tauri/source-icon.png` to regenerate all sizes.
